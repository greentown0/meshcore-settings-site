# Meshcore Netherlands — SF7 Settings site

Static bilingual site (EN / NL) built with [Eleventy](https://www.11ty.dev/) + Markdown. Deployed to Cloudflare Pages.

## Edit content

Content lives in two language files — **always update both** in the same change:

| File | Language |
|------|----------|
| `src/en/index.md` | English |
| `src/nl/index.md` | Dutch |

The shared HTML template (`src/_includes/base.njk`) handles the `<head>`, header, and footer.

### Custom Markdown containers

| Syntax | Purpose |
|--------|---------|
| `::: settings` | At-a-glance settings table |
| `::: step N "Title" "Summary"` | Numbered step card |
| `::: more "Label"` | Hover/tap popover inside a step |
| `::: cli "Label"` | Monospace command block with copy button |

All containers are closed with `:::`.

## Local preview

```bash
npm install   # once
npm start     # dev server at http://localhost:8080 with live reload
```

## Build

```bash
npm run build   # outputs to _site/
```

## Deploy (Cloudflare Pages)

1. Push this repository to GitHub.
2. In the Cloudflare Pages dashboard, connect the GitHub repository.
3. Use these build settings:
   - **Framework preset**: Eleventy
   - **Build command**: `npm run build`
   - **Output directory**: `_site`
   - **Node version**: leave blank — Cloudflare reads `.nvmrc` automatically.
4. Set the `SITE_URL` environment variable to your production domain (see below).
5. Every push to `main` triggers a new deployment automatically.

### Setting the canonical domain (`SITE_URL`)

All absolute URLs in the build (canonical, hreflang, Open Graph, sitemap, robots.txt)
are driven by a single environment variable. **Set it once and nothing else needs
touching when you change domains.**

In the Cloudflare Pages dashboard → **Settings → Environment variables**:

```
SITE_URL = https://yourdomain.com
```

That's it. No other changes needed.

**How it works:**

| Env variable set? | URL used |
|---|---|
| `SITE_URL` set | Uses `SITE_URL` |
| Only Cloudflare's `CF_PAGES_URL` present (preview builds) | Uses `CF_PAGES_URL` |
| Neither set (local dev) | Falls back to `https://settings.woodwar.com` |

The fallback in `src/_data/site.js` is only used locally. Production always reads from the env variable.

## Generate the Open Graph share image

The `src/assets/og-image.png` share card is generated by a standalone script using only Node.js built-ins (no extra dependencies):

```bash
node scripts/gen-og-image.js
```

Re-run this if you need to update the image. The result is committed to the repository and served as a static asset.

## File layout

```
src/
  en/
    index.md            ← English content
    en.11tydata.json    ← EN language data (brand name, nav labels)
  nl/
    index.md            ← Dutch content
    nl.11tydata.json    ← NL language data
  _includes/
    base.njk            ← shared HTML template (head, header, footer)
  _data/
    site.js             ← site-wide data (reads SITE_URL from env)
  assets/
    main.css            ← stylesheet
    main.js             ← copy-to-clipboard + popover behaviour
    og-image.png        ← Open Graph share image (1200×630)
  index.njk             ← root redirect page (geo-detects EN/NL)
  sitemap.njk           → builds /sitemap.xml
  robots.njk            → builds /robots.txt
scripts/
  gen-og-image.js       ← generates og-image.png (run manually)
.eleventy.js            ← build config
```
